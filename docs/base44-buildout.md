# Base44 integration buildout

This change completes the application paths for direct Google Calendar OAuth,
Firecrawl imports and Twilio SMS in DG Dashboard's existing Base44 source. It
builds on the connected repository's reconciled source and preserves Base44's
full-stack hosting adapters, canonical data model and database history.

Calendar uses the existing encrypted per-user connection store. Authorization
state is consumed atomically, the popup validates its sender/origin/state, and
Google codes are exchanged on the server with PKCE. Refresh writes cannot
recreate a connection removed during an in-flight request. Calendar imports
follow result pages, archive raw responses, record field provenance, retain
registration status and translate Google's exclusive all-day end dates. Timed
exports use a one-hour duration where the application has no stored end time.
New exports use a stable Google event ID. Retries verify the original event's
ownership markers and reconnect its receipt, preventing duplicate creation
after an interrupted response or local save.

Source readers share provider selection across course lookup, PDGA knowledge
and tour data, scheduled events, player/club imports, crawler jobs and disc
trends. Direct keys do not require Lovable. Successful Firecrawl responses and
direct public HTML are preserved through the existing snapshot writer.

SMS supports direct Twilio API credentials and either a sender number or a
Messaging Service. Missing credentials, invalid recipients, timeouts, provider
errors and missing receipts return a failed delivery result. Provider responses
and raw network errors are not exposed to players. Legacy installations keep
their explicitly configured gateway path; partial direct settings block a
request instead of switching providers.

Admin → Operations → Connectors reflects these runtime choices. The server
binding allowlist includes calendar encryption and Twilio settings. The new
OAuth callback has private cache/referrer headers and does not enter Supabase's
sign-in-code handler. Its route registry entry is generated by the normal
feature-registry script.

## Activation and verification

Follow [direct service setup](direct-service-setup.md) for private bindings,
Google callback registration and test account setup. Setting-presence checks
do not prove live account access. The local checkout does not currently contain
the direct provider credentials, and hosted private bindings remain unverified.

The application unit suite, script safeguards, TypeScript, both Worker builds,
local HTTP/access checks and popup tests are source verification. Browser
automation could not initialize in this session. Actual Google consent,
token refresh, event writes, source imports and delivery require the configured
Base44 preview and test accounts. No real SMS, email or paid AI request was sent.

The final source passed 1,198 tests across 142 files, 16 script safeguards,
TypeScript, production and Base44 full-stack builds, and 31 local HTTP/access
checks. The release check also verified that source stayed unchanged throughout
validation. These results do not establish hosted browser behavior or live
provider account access.

Base44's sandbox still times out, and its recorded source revision must be
reconciled with GitHub before merging or transferring these changes. The work
is isolated on `codex/base44-provider-buildout`; the original workspace and the
other chat's database restore are preserved. Follow
[the collaboration workflow](base44-codex-workflow.md). Source review is separate
from Publish, database migration and Storage/Auth cutover.
