# DGD engine rules

- DGD experience/familiarity diagnostics live in src/lib/dgd-v1/experience.ts and never modify DGD skill — keeps general ability separate from layout-specific residuals and stays shadow-only.
- DGD V1.1 candidate code lives in src/lib/dgd-v1/candidate*.ts under its own model id and never writes V1 rows — lets candidates be compared against a frozen control.
- DGD source-integrity diagnostics live in src/lib/dgd-v1/source-audit.ts and sourceIntegrityReport in shadow.server.ts; they are read-only and compare against a counterfactual world (toShadowRounds udiscRule:false) without writing — keeps audits side-effect free and the single unified model untouched.
- DGD recent-performance diagnostics (Form value vs Form-vs-Skill, layout state, directional PDGA/DGD comparison, evidence weights by age) live in src/lib/dgd-v1/recent-audit.ts and are read-only — audits never change V1.1 math or stored ratings.
- DGD V1.2 candidate code lives in src/lib/dgd-v1/candidate-v12.ts under its own model id with a frozen, versioned reference frame (V12_REFERENCE) — layout priors never come from a live population average, so unrelated players can't shift each other's Skill.
- Recovered PDGA course/layout context lives in pdga_round_context (provenance, superseded rows kept) built by src/lib/dgd-v1/pdga-context.ts + v12.server.ts; imported external_rounds values are never overwritten — enrichment stays auditable and replayable.
- Source inconsistencies are stored as SOURCE_CONFLICT rows in dgd_source_conflicts (detectRatingConflicts in v12-shadow.ts) and never change layouts or ratings — conflicts stay reviewable and source-grounded.
- DGD V1.3 candidates live in src/lib/dgd-v1/candidate-v13.ts as frozen optional hooks (prior, forecastMu) passed to the unchanged V1.2 engine; V1.2 never sets them and the updater never runs V1.3 — the control stays bit-identical.
- DGD V1.3 research version (dgd-core-v1.3@0.3.0 = frozen Candidate D) runs in the same queue worker beside V1.2 and writes only dgd_v13_* state plus model-tagged round rows — admin-only, never player-facing, never alters V1.2 output.
- Model promotion stages, the public whole-number rounding rule, launch gates and the source-mix harness live only in src/lib/dgd-v1/launch-readiness.ts (stage mirrored in rating_model_versions.shadow_stage) — one queryable source for promotion and launch decisions; gates change only with evidence.
- The public DGD scale is dgd-scale-1000-v1 (SQL dgd_scale_1000*, TS mirror scale-1000.ts used only by tests/dry runs); public RPCs apply it server-side and the UI renders whole numbers — the scale can change without touching Skill or UI math.
- DGD Tier (experience & contribution) lives in src/lib/dgd-tier/engine.ts (pure, versioned, no rating input) and tier.server.ts (service-role worker run by the DGD worker route from dgd_tier_jobs) — Tier stays independent of Rating and server-authoritative.
- DGD V1.1 shadow results are produced only by the queue worker in src/lib/dgd-v1/shadow.server.ts from canonical rounds via shadow-input.ts; database triggers enqueue per-player jobs on evidence changes and wake the worker, writes are diff-only so repeats converge — keeps Statboard read-only and calculations idempotent.
- V1.1 player state stores FORM_VALUE (form_value) and FORM_MINUS_SKILL (form_delta) separately; UI labels the difference only as "Form vs Rating"; "Skill"/"Latent Skill" is admin-only wording for the unscaled model value — one word never names two quantities.
- DGD V1.2 shadow champion (dgd-core-v1.2@0.2.0, V12_SHADOW_FLAGS) runs in the same queue worker as V1.1 via loadV12World in v12.server.ts; it writes dgd_v12_player_state (superseded states kept in dgd_v12_state_history) and model-tagged rows in dgd_v11_round_results, and players read it only through get_my_dgd_preview_summary_v2 / rounds_v4 (V1.1 control admin-only) — one updater, frozen models side by side.
- Every insert into dgd_v11_jobs wakes the worker through one statement-level trigger; a full worker batch re-wakes itself and the hourly cron is only a backstop — one wake path, claim-locked so runs never double-process.

- DGD V1 rating math lives only in src/lib/dgd-v1/engine.ts and runs server-side via run.server.ts writing through dgd_v1_apply_player — keeps calculations auditable, transactional, and out of the browser.
- DGD pre-round forecasts never use any score from the round being predicted; same-round field data only produces a separate post-round event-round adjustment that is never written into persistent layout difficulty — keeps accuracy claims leakage-free and baselines stable.
- DGD V1.1 preview data is precomputed by an admin job into dgd_v11_* tables and read by players only through SECURITY DEFINER functions gated by dgd_preview_allowed() and auth.uid(); UI shows supplied display values and never transforms latent skill — Statboard never triggers recalculation and the display scale can change without UI edits.
- DGD public display scales are versioned rows in dgd_display_scales (definitions in src/lib/dgd-v1/display-scale.ts, independent of model_version); the backend stores per-player values in dgd_v12_display_candidates and UI only renders them via get_my_dgd_scale_candidates — scale changes replay safely without touching latent Skill.
- DGD percentiles are computed only against a versioned dgd_benchmark_versions row (explicit population definition + sample size) and never feed back into Skill or Rating; calibration subjects carry cohort VALIDATION_STRATIFIED vs BENCHMARK_RANDOM so model-coverage sampling never defines percentiles.

- UDisc format/player-count classification lives only in src/lib/udisc-eligibility.ts; the importer stores it on external_rounds and shadow-input.ts excludes UDisc-only rounds that are not SINGLES_MULTI_PLAYER — one rule shared by import and rating, native UDisc ratings stay source-owned in round_rating.
- PDGA's current-rating-window flag (external_rounds.included) never decides DGD V1.1 eligibility; restoreHistoricalPdga in shadow-input.ts re-admits singles PDGA rounds excluded only for that reason and leaves the flag untouched — PDGA window is a PDGA concept, and V1.1 recency handles age.
