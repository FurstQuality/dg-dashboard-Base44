- Tee/basket coordinates from outside sources land first in course_geometry_observations (one row per source feature, written only by src/lib/course-geometry/harvest.server.ts) and reach holes only by filling empty spots — never overwriting — so source data stays auditable and steward geometry is never clobbered.
- Physical holes/tee pads/basket positions live in course_holes/course_tees/course_baskets independent of layouts; the harvester attaches explicitly numbered source pins to the one existing hole with that number (never beside hand-built holes, skips numbers shared by several holes), creates holes only on courses with none, and drafts a layout only when a course has no layouts — one row per source observation (source_observation_id unique) — layouts reference physical assets, never the reverse.
- A course's map state (unmapped/partial/starter/verified) is computed only by the course_map_coverage_rows SQL function from real tee+basket coordinates — one definition for every screen.
